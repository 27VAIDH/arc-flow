## Codebase Patterns
- Schema migrations follow pattern: migrateToVN() reads workspaces, patches missing fields with defaults, writes back with version N
- Each migration function should set schema version to its own number (not CURRENT_SCHEMA_VERSION) so migrations chain correctly
- ensureInitialized() chains migrations with `if (version < N)` blocks
- createWorkspace() deep-copies with new UUIDs when cloning — remember to clone new array fields too
- Test fixtures for Workspace objects are in commandRegistry.test.ts — update when adding new required fields
- Quality commands: `npm run typecheck` and `npm run test:run`
- folderStorage.ts is a facade layer: each function gets active workspace ID then delegates to workspaceStorage.ts
- Saved items CRUD in workspaceStorage.ts follows same patterns as folder items CRUD (get workspaces, find ws, mutate, save)
- DnD item prefixes: `tab:`, `folder:`, `folder-item:`, `saved-item:`, `pinned:` — each has corresponding drag start/end cases
- savedItems state syncs via the existing workspaces storage change listener (no separate listener needed)
- Context menu handlers build ContextMenuItem[] array and call setContextMenu — add savedItems to deps when referencing it
- customCollisionDetection priority: folder-drop > zone targets (pinned/tablist/saved-items) > pointer collisions > rect intersection
- Droppable zones must always render their ref element (even if hidden) so dnd-kit can detect them as drop targets
